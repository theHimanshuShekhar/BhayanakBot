Requires Administrator, and is hidden from members without Manage Server. `add` supports `match-type`, `use-llm`, `use-regex`, channel filters, mention requirements, chance, and trigger deletion. LLM auto-responses are a Home Server feature: `use-llm` is refused in other servers, and an LLM rule fires in any Home Server channel its channel filter allows (it is skipped everywhere else, so its prompt is never posted). Your prompt is combined with the server and member personality profiles and the channel's last 20 messages, fetched live from Discord (the bot's own replies included, labelled as its own). The reply shows typing while it is written and refers to people by plain display name. A message gets at most one bot reply: a matching autoresponse, static or LLM, answers first, so a bot mention on a message that matches a rule gets the rule's reply and not a second one. Each trigger has a 10-minute cooldown (a bot mention bypasses it) and each member 30 seconds; both start only after a reply is sent. If the AI provider returns nothing, nothing is posted, a delete-trigger message is kept, and cooldowns are not used up. `remove` deletes by trigger and `list` shows configured responses.

## Regex triggers

With `use-regex:true` the trigger is matched case-insensitively anywhere in the message, using the RE2 engine, so a pattern can never hang the bot.

- Supported: character classes, groups, alternation, repetition (`*`, `+`, `?`, `{n,m}`), anchors, and named capture groups written `(?<name>...)`. Each capture is substituted into the response wherever `{name}` appears.
- Not supported: lookarounds (`(?=...)`, `(?!...)`, `(?<=...)`, `(?<!...)`) and backreferences (`\1`). `add` rejects them with an explanation.
- Patterns are limited to 100 characters, and only the first 2000 characters of a message are checked.
- A stored pattern that is no longer valid under these rules never runs. `list` shows it with a `DISABLED: unsupported regex` marker; remove it and add a corrected one.
